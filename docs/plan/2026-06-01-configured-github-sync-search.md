# Configured GitHub Sync and Search Fix

## User Request

GitHub-backed answer/search also misses existing repositories/documents, including `eunhwa99/neetcode-submissions-8ogaz8xl` when asked in Korean for NeetCode docs and `ImageGallery` when searched by repository name.

## Scope and Non-Goals

- Fix browser-visible sync progress so configured source sync does not look permanently stuck during GitHub document discovery and terminal states are rendered clearly.
- Improve ContextWiki search/answer recall for GitHub repository names, paths, titles, and Korean queries that mention NeetCode/GitHub/docs.
- Preserve current MCP tool names, parameters, and response shapes.
- Do not inspect, delete, reset, or migrate local user Chroma/SQLite data.
- Do not run live configured-source sync or mutate user data without explicit approval.
- Do not add OAuth, persistent source registration UI, or a new MCP contract.

## Acceptance Criteria

- A configured GitHub sync with a running job that has no discovered document total yet shows an honest discovery/fetching status rather than looking idle forever.
- A terminal sync job with zero discovered documents or a failure renders as terminal instead of `Discovering documents...`.
- `answer_with_citations("니트코드 문서 찾아와")` can ground on indexed GitHub evidence whose repository/title/path contains `neetcode` even if the exact English word is outside the chunk text.
- `search_context("ImageGallery")` can return indexed GitHub chunks when the repository name appears in title/path/url/document identity, not only in chunk body.
- Focused tests fail before implementation and pass after the fix.

## Architecture / ADR Constraints

- ADR 0002: SQLite metadata remains the authoritative citation/job store; tests use fake/temp persistence.
- ADR 0003: Preserve source-aware document/chunk identity and active retrieval gates.
- ADR 0004: Keep GitHub connector under `fetching/`, configured source id `source_github`, and avoid live external validation unless approved.
- Architecture doc: search behavior belongs under `search/`; browser progress belongs under `web/` and `web_console/`; API tool contracts stay stable.

## Risks and Rollback Notes

- Query expansion can reduce precision if metadata matching is too broad; keep repo/path matching deterministic and score-bounded.
- UI progress changes must not hide real failures or already-running states.
- Rollback point is this branch before production code edits; no local user data mutation is planned.
